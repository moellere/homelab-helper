Title: `Add minute forecast (forecast/minutes:lookup) support`

---

Adds support for the experimental [minute forecast endpoint](https://developers.google.com/maps/documentation/weather/minute-forecast):

- `GoogleWeatherApi.async_get_minute_forecast(latitude, longitude, page_size=360)` returning a new `MinuteForecastResponse`.
- `PrecipitationSegment` model with nested `DominantPrecipitationType` (`NONE`/`RAIN`/`SNOW`/`HAIL`) and `PrecipitationIntensity` (`NO_INTENSITY`, `LIGHT`, `MID_LIGHT`, `MODERATE`, `MID_MODERATE`, `HEAVY`, `MID_HEAVY`) enums.
- Field names, enum values, and optionality follow the published `google.maps.weather.v1` protos in [googleapis/googleapis](https://github.com/googleapis/googleapis/tree/master/google/maps/weather/v1) (`forecast_minute.proto`, `weather_service.proto`), matching the style of the existing models.
- Note: `language_code` is a **reserved field** on `LookupForecastMinutesRequest`, so `_async_get` gained an opt-out and this endpoint does not send it (sending unknown query params gets rejected by gRPC transcoding).
- Proto3-default fields that the JSON encoding omits (`probability` 0, `qpf`/`snowfallAmount` unset, empty `segments`) are modeled with defaults, covered by tests.

Ran `ruff check`, `ruff format --check`, `mypy src` (strict), and `pytest` — all green.

Motivation: I'd like to expose this in the Home Assistant `google_weather` integration as an on-demand `get_minute_forecast` entity service (mirroring `openweathermap.get_minute_forecast`); a core PR is ready to go once this lands in a release. Happy to adjust anything to your preferences.
